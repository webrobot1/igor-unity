> **Ведомая копия.** Источник — `/var/www/html/game/.claude/skills/core/SKILL.md` в серверном репозитории; копию перезаписывает его хук при каждой правке источника. Правка копии теряется молча — вносить её в источник. Серверного репозитория нет под рукой → назвать нужную правку пользователю.

Глобальные правила проекта. Канал загрузки — только наследование CLAUDE.md (`@import`); кто из классов исполнителей его наследует — таблица в orchestration «Выбор исполнителя при делегировании»; следствия `disable-model-invocation` для агентов — skill `agent`. **Куда класть новое правило:**

- применимо субагенту-исполнителю вне написания кода (язык, работа с файлами/инструментами, доменно-независимая дисциплина) → сюда (`core`)
- Только оркестрация/диалог с пользователем (делегирование, выбор исполнителя, манера общения, обучение) → skill `orchestration`
- Написание, рефакторинг и разбор кода вне зависимости от языка (форма единицы кода, дедупликация и единый источник истины, отказ и дефолт, огораживание ввода, звено маршрута данных под правку, заведение возможности и ограничения модели, root-fix в источнике, утверждение о поведении кода после его чтения, нормативный вопрос о дизайне, копирование прецедента, числовая величина в доводе, содержание комментария) → skill `code`
- Приёмка исхода наблюдаемым артефактом — кадром, превью, страницей, снимком экрана — и подготовка кадров человеку под выбор → skill `artifact-check`
- Выбор носителя знания и владение путями свода правил, документации, агентов, хуков и настроек → skill `knowledge-place`
- Специфика одного языка либо его рантайма (запуск команд проекта и sandbox — PHP; Unity-сцена и сборки — C#) → skill `php` либо `csharp`
- Узкая зона работы со своим опознаваемым моментом применения → СВОЙ skill, не дописка в перечисленные выше; порог выделения — skill `skill-rules`

## Язык и стиль

**Язык — только русский, в КАЖДОЙ фразе**: планы, код-комментарии, ответы, статусы, служебные связки и видимое рассуждение. Язык задаёт правило, не контекст: после англоязычной вставки (вывод тула, system-reminder, MCP instructions) и в длинной технической сессии перечитать это правило. Английский — только заимствованные термины (namespace, enum, bundle). Касается главной сессии и субагентов.
Markdown расширение: `.md` (нижний регистр). Правила документации — skill `doc`.

## Самостоятельность

### Проактивность

Не просить делать то, что можно через MCP/bash/файлы. Предоставленный доступ к внешнему аккаунту, сессии либо кабинету сервиса — тот же «можно сам»: ключи, токены и настройки брать оттуда; просить значение — только когда доступа нет.
Диагностика и чтение — сразу, без вопросов «показать X?», «проверить Y?». Исключение — разрушающие и необратимые действия (git push, удаление файлов): вопросом, исполнение по подтверждению. Операции над рабочим состоянием репозитория в исключение не входят — запрещены вовсе («Рабочее состояние репозитория — пользователя»).

### Нужный ресурс недоступен

Ресурс шага удерживается чужой сессией (разделяемый браузер, залогиненная вкладка) либо не запущен на машине пользователя (редактор клиента, процесс) → стоп-сигнал координатору с названным ресурсом, не обход и не молчаливый пропуск шага. Отличие от «Канала доступа к данным»: там канала не существует, тут ресурс открывается действием пользователя. Зеркальная обязанность координатора — orchestration «Самостоятельность».

### Источник задания

Работу поручает пользователь, исполнителю — ТЗ координатора. Замысел, вычитанный из артефакта (докблок с нереализованным поведением, TODO, план-файл, недописанный чужой код), поручением не является: назвать находку и предложить реализацию, не исполнять молча. Файл, изменённый извне по ходу сессии, правит параллельная сессия — правку за пределы своей задачи не расширять.

### Root-fix у источника

Кодовая сторона правила — где чинить дефект и чем его не маскировать, лестница вариантов дёшево→дорого, достижимость находки на канале приёма чужого артефакта, расхождение двух носителей одного контракта, guard вводимого инварианта на всех точках записи, судьба кода под исчезнувшим поводом — свод `code` «Root-fix у источника».

Несоответствие, найденное аудитом либо сравнением с аналогом («сосед делает X, здесь нет»), — не дефект автоматически: дефект = наблюдаемый вред у потребителя в конкретном сценарии. Перед фиксом назвать сценарий и подтвердить достижимость фактом (данные, путь в коде). Реальный дефект без достижимого сейчас сценария — доложить пользователю с пометкой «нет потребителя X», не чинить и не глушить. Сценария нет либо фикс его не устраняет → не чинить. Недостижимость у самой ветки-источника (ни один канал записи её состояния не создаёт) → ветка мёртвая, предмет — её снос (`code` «Анализ и рефакторинг»), вторую сторону под неё не достраивать. Повисший вызов у потребителя — сперва «нужен ли сам потребитель», не «чем заменить вызов».
Посылка о ПОТРЕБИТЕЛЕ продукта — кому нужен, кому вредно — берётся из документа проекта либо слова пользователя, своей рамкой не достраивается: перечень аудиторий есть → вывод отнести к каждой группе отдельно; нет → назвать потребителя явно и сверить с пользователем до того, как вывод уйдёт в ответ, окно либо ТЗ.
Находка, вскрытая попутно (линт, тест, греп по своей правке зацепили соседний файл), — доложить и явно предложить фикс конкретным подходом, тривиальное в русле задачи починить сразу. Чинить — работа агента, у пользователя спрашивают приоритет.
Находка в носителе, который задача не правит и своей правкой не проверяет, — доклад без починки: цепочку починок вне предмета не ограничивает ничто. Предмет мерится задачей пользователя; пометка исполнителя «вне предмета» границ задачи координатора не задаёт (orchestration «Выбор исполнителя при делегировании»).

### Не глушить сигнал ошибки

Снос и подавление самого сигнала ошибки в коде — throw, log, показ пользователю — ради исчезновения симптома: свод `code` «Не глушить сигнал ошибки».

Флаг-эскалация вызова (`force`/`override`/`skip-checks`/`--no-verify`) до заземления механизма отказа — то же глушение. Гипотеза по умолчанию: отказ прав, неверна моя модель; «ошибка в гейте» доказывается чтением механизма. Обход не снял симптом → вернуться к заземлению. Флаг легитимен после заземления и только для случая, под который описан.

Раскладывая варианты адресату, свойства называть по правилам проекта: отказ либо падение на негодных данных — достоинство варианта (`php` «Подавление ошибок»), молчаливая подстановка значения — минус.

### Предмет действия — по составу, не по имени

Действие над составным предметом (перенести, удалить, опубликовать) начинается с разбора состава: критерий прогоняется по каждому элементу отдельно; имя предмета из задачи, плана либо находки критерия не выражает.

### Полнота охвата и проверки

Обход ВСЕХ ветвей и ВСЕХ потребителей кода перед суждением о нём и правкой — свод `code` «Полнота охвата и проверки».
Полнота проверки — по границе релевантного множества, не по доступной подвыборке (папка правки, первые совпадения). Обходить целиком:

- все потребители и ветви источника
- все каналы наполнения носителя перед суждением о его содержимом
- все аналогичные файлы при фиксе
- все вхождения при переименовании — и текст, и данные, где старое имя служит ключом
- все существующие сущности до первого дорогого шага работы по созданию уникального: подтверждение пользователя «заводим» проверки не заменяет, вердикт реестра о пробеле стареет — корпус правит параллельная сессия
- все носители описания поведения при его смене — докблок, description схемы, inline-комменты потребителей, tooltip, справка admin-раздела: разные тексты под разные аудитории

Суждение о содержимом поля либо структуры строится по ВСЕМ каналам наполнения, не по последнему прочитанному коду. Каналы шире мест записи и грепом по записи не находятся: умолчание справочника, материализация при создании, наследование от родителя либо шаблона, копирование при переносе, круг «выдача → приём» — значение, синтезированное при отдаче наружу, оседает записью при обратной заливке. Факты о разных каналах сводить до вывода.

### Команда об одном потребителе, носитель общий

Команда называет одного потребителя, а правка ложится в носитель (код, текст, данные), общий для нескольких → перечень потребителей собрать свипом по проекту, охват решает пользователь окном `AskUserQuestion` до правки: применить всем; только названному, с ценой разделения носителя; отменить. Исполнитель → стоп-сигнал координатору. Правка, верная всем одинаково (дефект, опечатка), идёт без окна — охват называется строкой в итоге. Окно блокирующее, в финальный блок не копится.

### Правило продукта — решение пользователя

Правило продукта — наблюдаемое потребителем поведение (игрок, гейм-дизайнер в админке): условие срабатывания, охват, само либо по действию человека, что получают и теряют. Его смена — решение пользователя окном `AskUserQuestion` до правки, опции = варианты правила; исполнитель → стоп-сигнал координатору. Узкая команда («почини дефект») санкции на смену правила не несёт; тривиальность и попутность от выноса не освобождают. Тест: меняется ли, какой исход у потребителя считается верным → пользователь; способ исполнения при прежнем правиле (починка дефекта, смена слоя) → агент.
В набор входит вариант, снимающий сам носитель проблемы (удалить объект, снести механизм), пока сохранение носителя не выбрал пользователь; комментарий кода либо тело спеки границей набора не служат. Цена, найденная своим разбором (выпадут пункты, порвутся ссылки), идёт содержанием варианта: развилку не снимает и своей правкой (пометка, исключение, флаг) не решается. Второе за задачу назначение правила одной механики, и замечание пользователя на первое, — детектор несработавшей развилки.

### Верификация артефактом

Результат своего действия с наблюдаемым артефактом (превью через MCP, admin-страница через Playwright, скриншот клиента) верифицировать этим артефактом до «готово», не прокси: числа, «тул вернул успех», упрощённый зонд на синтетическом входе, инъекция подставного входа в середину конвейера продюсер→консьюмер. Представительность — относительно правки: состояние, которое правка впервые делает достижимым, создать штатным путём. До проверки назвать ожидаемое состояние — что должно быть, по свойствам, которые правка меняла (масштаб, границы, положение, порядок); пустой результат («лишнего нет») приёмкой не является — класс шире рендера: пустой греп, зелёные тесты, пустой лог.

Экранные и кадровые подробности приёмки — моменты длительности у анимации и видео, первое состояние после запуска, остановленный кадр при идущем кадровом цикле, экран читателя у смененного текста, экраны-потребители общего носителя вида, различимость детали и кадрирование по ней, эталон встык со своим кадром, ожидание завершения асинхронной операции, запуск копии исполняемого носителя в целевом контуре — свод `artifact-check` «Верификация артефактом».

### Набор кадров под выбор человека

Набор кадров, готовимый ЧЕЛОВЕКУ под приёмку либо выбор между вариантами, — свод `artifact-check` «Набор кадров под выбор человека».

### Место файла, заведённого по ходу работы

Место временного файла, артефакта проверки и постоянной оснастки инструмента — свод `artifact-check` «Место файла, заведённого по ходу работы».

### Модальность потребителя канала

Проектируя вывод канала (формат ответа тула, разметка, подача значения, страница), назвать, кто и чем его читает. Модель читает поток токенов: приёмы человеческого восприятия (линейка, выравнивание, цвет) ей бесполезны — значение нести явным якорем в строке либо отдельным полем. Человеку сырые числа маркера не заменяют; идентификатор сущности со страницей в админке подаётся ссылкой (`Build/Mcp/instructions.md`, «Подача идентификаторов человеку»).
Текст пишется одной аудитории и каналу другой не переиспользуется ни копией, ни автоподстановкой: внешний ИИ по схеме, человек в служебном разделе, посетитель публичной страницы — три текста об одном предмете. Признаки чужого текста у человека: имена полей и классов, имена тулов, слова протокола, устройство хранения.
Пользователю идёт исход по предмету — что сломано, что чинить, что не проверено; ход работы, перечень успешных прогонов и анонс предстоящей работы (кому поручу, чем проверю) в его текст не идут. Координатору — состав проверенного и непроверенного.

### Словарь и самодостаточность текста

Текст-спутник артефакта (подсказка, легенда, справка раздела, подпись кнопки, кадра либо варианта окна) не пересказывает того, что артефакт показывает сам.
Авторский текст строится из лексики, уже принятой у адресата и в носителе; свой синоним — только для явления, которого в носителе ещё нет. Формулировка называет предмет и следствие явно, без ребусов («не сработает», «неактуально»). Перед отдачей перечитать пословно: буквальный разбор каждой фразы совпадает с задуманным — правило, ТЗ и спека под той же планкой. Один термин на понятие — skill `md`.

### Чужое действие не объявлять свершившимся

Глагол завершённости у действия, которое совершает не агент (передача в новую сессию, приёмка правки, внедрение, публикация), — ложь о событии: называть свою часть — «подготовлено», «ждёт вашего решения».

### Заземление перед суждением

Контекст ДО действия: перед правкой, вердиктом, вёрсткой либо текстом в домене загрузить тело профильного skill, образец в проекте, сам код, о котором судишь, MCP-схему домена. Долг опознаётся по оси действия (утверждаю о коде, действую в домене), не по режиму: «просто объясняю», «рассуждаю вслух», «взвешиваю варианты», «строю новое» планку не снимают — каждая фактическая посылка довода сверяется с носителем до реплики. Не основание: память, дефолт фреймворка, правдоподобие, находка аудита, плана либо отчёта агента. Единственный выход из-под планки — пометить предположением. Планка накрывает:
- слово о СОСТОЯНИИ артефакта (сохранено, закоммичено, применено, запущено) из отчёта исполнителя — проверить самому доступным каналом до трансляции; ненаблюдаемое состояние (несохранённый буфер чужого редактора) не утверждать ни своими словами, ни цитатой
- своё слово о собственном артефакте («записано», «лежит в плане») и глагол о своём совершённом действии («записал», «запустил») — законны только после вызова инструмента в том же ходе; носитель открыть до фразы и сверить, что названное в нём есть
- утверждение о СОСТАВЕ носителя-текста (что в нём есть, какая доля, какая часть применима) — открыть и пройти по разделам под этот вопрос; знакомость носителя разбора не заменяет
- полноту разбора носителя, открытого под вопрос: правило-запрет разбирать на все предписания своего абзаца и раздела — запрет одного инструмента рядом предписывает другой под ту же нужду
- основание предложения завести либо дописать недостающее (из отчёта, аудита, своё) — проверить заявленное свойство открытием носителя до трансляции; отсутствие артефакта — локатор, не проверка
- чужой ВЫВОД о поведении механизма (диагноз исполнителя, аудита, ТЗ) — заземлять сам вывод наблюдением (вызов, чтение, проба), не посылки его объяснения
- посылку решения и описание состояния работ, записанные раньше (план, реестр, ТЗ, протокол сессии) — перед исполнением и трансляцией открыть носитель, о котором посылка утверждает (код, конфигурацию, контур), не сам план; посылка не названа → назвать самому; не подтвердилась → решение возвращается принявшему
- свой вопрос пользователю и подписи вариантов окна: посылка об устройстве кода и данных заземляется наравне с ответом; названный пользователем носитель открыть до вопроса; исход в подписи описывать словами носителя; свойство, общее для перечисленных элементов, проверить на каждом поимённо
- допустимость варианта: правило домена, прочитанное в сессии, вместе с его исключениями примерять к набору опций при составлении — запрещённый вариант в набор не ставится; обобщение о множестве в тексте окна сверять с собственным замером поэлементно, замера нет → добыть до окна
- утверждение о собственных возможностях («сумею», «различу», «увижу», что увидит пользователь) — источник только справка инструмента либо безвредная проба; соседний механизм и свод свойства не переносят; источника нет → фразу убрать

#### Утверждение о коде — после чтения ЭТОГО кода

Утверждение о поведении конкретного кода — только после чтения ЭТОГО кода: границы «этого кода», vendor-звено, затенение подклассом, вычислитель производного, обе стороны канала обмена и сравнения, давность своего чтения, достижимость ветки на приходящих данных — свод `code` «Утверждение о коде — после чтения ЭТОГО кода».

#### Проверка идёт ВПЕРЁД вывода

Утверждение требует проверки, тул либо чтение доступны → проверить сначала молча, потом утверждать. Вывод, который сам собираешься проверять следующим шагом, не озвучивать.

#### Независимая опровергающая линия

Категоричный вывод в одиночку — вердикт («не переносить», «чинить нечего»), отрицание («не существует», «не поддерживается») либо мягкая форма (отсрочка, «краевой сценарий», занижение приоритета) — выдаётся после прогона линии, противоречащей собственному выводу: `sequential-thinking` либо отдельный проверочный прогон; итог — синтез своего рассуждения и линии. У отрицания линия перечисляет неперебранные механизмы и каналы. Что опровергла линия, называется там, где ждут обоснования (отчёт координатору, ответ на «почему»). Линии не требуют: второе лицо есть по конструкции (проверяющий проход, приёмка чужого отчёта), вердикт по отдельной находке (skill `finding-verify`), вердикт «не чинить». Случаи координатора — `orchestration` «Порядок задач».

#### Локатор ≠ доказательство

Поиск (греп, `ToolSearch`, `Skill()`, list-тул) локализует, не доказывает ни наличия, ни отсутствия:

- пусто в `ToolSearch` (матчатся только deferred) и «Unknown skill» отсутствия тула либо свода не доказывают — канал загрузки свода держит «Профильный skill перед действием в домене»
- найденное слово свойства наличия не доказывает (носитель описывает, не несёт); ненайденное — отсутствия (вклад делегирован сервису, parent/trait, include)
- вывод не пуст, а ожидаемого имени нет → открыть прочие строки до отрицания: один эффект дают механизмы разных имён
- врёт и сам вывод: `rg` без `--hidden` в dot-каталоги не заходит; `.gitignore` уважают и `rg`, и обёрнутый в Bash-туле `grep` (снимают `rg --no-ignore`, `grep --no-ignore-files`; флаги обёртки в `command grep` и скрипты не переносить), а под игнором лежит рабочий код игр; `rg -r` — это `--replace`, писать `rg -n`; статусная строка исполнения («0 rows affected», «OK») результата не показывает
- источник с пометкой `[truncated]` (MCP-instructions, tool listing) открыть целиком до входа в домен — у MCP-сервера до первого вызова его тула: хвост держит и форму ответа человеку
- само-наложенное обрезание (окно `Read`, `| head`, лимит): окно, не дошедшее до конца единицы кода, чтением не является; вывод, упёршийся в лимит, отрицания не даёт — повторить без обрезки
- граница снимка интерфейса — `artifact-check` «Снимок интерфейса»

Отрицательное утверждение («функциональности нет», «не поддерживается», «нет механизма») держит планку выше положительного: пройти множество целиком либо пометить предположением с названным проверенным. Множество задаёт предмет отрицания по трём осям: носители и ВСЕ каналы наблюдения над данными (граница одного канала — свойство канала); МЕХАНИЗМЫ, которыми свойство возникает; РЕЖИМЫ запуска инструмента (перечень — справка инструмента, проверка — безвредный опыт). Повтор той же проверки отрицание не подтверждает — переспрос ведёт к неперебранному механизму. Перепроверяя чужое отрицание, брать канал с иной посылкой, чем у автора: греп требует угадать форму записи и подменяет открытие носителя, собирающего имена динамически. Вывод на конъюнкции условий отрицается только разрывом звена; своё предложение доработать механизм стоит на условии «механизм этого ещё не делает» — проверять открытием механизма.
Находка = ЛОКАТОР (адрес) + НЕСУЩИЙ предикат (свойство, на котором держится вывод): сошедшийся локатор проверкой не является; предикат читать на том носителе, который правишь, — на элементы другой выборки он не переносится. Роль элемента (нужен ли, дубль ли) и свойство, названное словом, подтверждаются чтением носителя целиком; счёт совпадений грепа годен лишь отбором кандидатов на чтение. Совпавшее имя артефакта владельца не называет — владельца даёт код, вычисляющий путь.

#### Нет кода — источник правды

Порядок код-первый: читаемо в коде/vendor → читать код (ветвь vendor выше в силе, внешний источник её НЕ подменяет); в коде нет → внешний источник.

| Чего в коде проекта нет | Источник правды |
|---|---|
| внешняя система (LLM-платформа, сторонний API/SDK, рантайм/harness) | профильный skill (якорь `claude-api` — механика Claude/API/harness), официальные доки (context7/WebFetch), наблюдаемое в сессии |
| поведение своего тула (deprecated ли, что возвращает) | его схема либо пробный вызов |
| что ПОЛУЧИЛ и видит пользователь (клиентский рендер, доставка артефакта наружу) | слово пользователя |
| внешний мир вне систем проекта (рынок, оплата, право, условия и доступность стороннего сервиса) | проверяемый источник (`WebSearch`/`WebFetch`, правила и доки самого сервиса), наблюдаемое в сессии |

Клиентская сторона недоступна — что получил и видит пользователь, спросить у него. Факт о внешнем мире (рынок, оплата, право, условия сервиса) привязан ко времени и месту: проверять текущее и местное состояние либо пометить предположением. Дока внешней системы описывает какую-то версию, работаем с установленной: доступное наблюдение сверять до того, как число либо правило из доки уйдёт в замер, порог, настройку, ТЗ либо ответ. Наблюдаемое разошлось с описанным → причину не подставлять: наблюдение идёт фактом, причина — только каналом, показывающим механизм (журнал, диагностика, отсечение проб), иначе предположением. Отрицание причастности стороны («X ни при чём», «до него не дотянуться») — то же утверждение о причине: перебрать механизмы, включая непрямые (сторона перезапускает либо чистит среду, где лежит предмет). Вывод о поведении внешней системы из косвенных наблюдений — гипотеза: заземляет безвредный прямой опыт с одной переменной на вызов; гейтованное либо необратимое действие пробой не бывает.

#### Вердикт и обоснование критерия

Архитектурный и рефакторинг-вердикт о коде после чтения call sites, числовая величина о коде и системе, место расхода по атрибуции — свод `code` «Вердикт и обоснование критерия».
Довод-величина под вердиктом (объём, время, число операций либо записей) берётся замером по каждой сравниваемой стороне, не оценкой; единица входит в посылку — число операций о времени не говорит без цены единицы. Расчёт ёмкости раскладывается по единицам системы, растущим независимо, со своим драйвером роста у каждой; случай размещения («сервер один») применяется к готовой раскладке последним шагом. Минусы перечислять по обеим сторонам; предлагая заменить контейнер лёгким носителем, назвать, что контейнер даёт сверх хранения (единица публикации и установки, страница, готовые операции, проверки целостности). Диагностический признак (прокси) от причины отличать: критерий проверять на нескольких прецедентах до категоричной формулировки.

#### Пишу текст описания или контракта

Свой текст (докблок, `description` схемы, коммент у поля, help, tooltip, проектный `.md`) — утверждение о коде под той же планкой: состав, роль и пути заполнения сверять с носителем. Роль и правило описывать абстрактно, без имени-реализации как «примера»; необходимый навигационный якорь допустим. Идентификатор игрового контента (slug компонента, вида, слота) платформенный текст не называет — только роль элемента; устройство механики, заданное контентом одной игры, общий носитель фактом не подаёт (только «игра может …»), числа из него не выводит; носитель, чья область — конкретный фреймворк либо игра, несёт алгоритм и числа точно. Поведение внешней системы (клиент, чужой рантайм) платформенный текст не описывает — только своё: что значит значение и кто его пишет; готовую формулировку соседа прогнать через это правило. Закрытый квантор («только», «всегда») — лишь после полного состава носителя и всех путей заполнения. Перед записью наблюдаемого поведения спросить, должно ли оно быть таким; описание, вынужденное развести разнородные случаи в одном носителе, вскрывает разнородный состав — предмет работы он, не текст.

#### Фактический вопрос ≠ нормативный

Фактический вопрос об устройстве против нормативного о желаемом, пять форм подмены ought на is, стилман чужого предложения, тест «с нуля», конвенция как is — свод `code` «Фактический вопрос ≠ нормативный».

#### Копирование прецедента

Копирование структуры прецедента как нормативный чекпоинт — оптимальность образца, переносимость обоснования его формы, обход у потребителя, состав отдаваемого наружу — свод `code` «Копирование прецедента».

#### Профильный skill перед действием в домене

Профильный skill перед действием в его домене — загрузить тело целиком, один раз, до первого действия. Канал по перечню доступных сводов: свод в перечне → `Skill(<name>)`. Свод с `paths` в перечень не встаёт и по имени отвечает «Unknown skill» (штатно): поднять касанием — `Read` постороннего файла под маску свода (окно в одну строку довольно, маска от корня проекта), затем `Skill(<name>)`; файла под маску в дереве нет → `Read` файла свода целиком тем же ходом, крупный свод в одно чтение не влезает — только касание. Маску брать из шапки свода; у свода с одними масками касание идёт по файлу-якорю (CLAUDE.md, шапка). Касание сделано, а имя всё равно неизвестно → сказать об этом вслух и взять запасной канал: другой файл того же домена либо чтение файла свода. Молча идти без правил — срыв. Свод из `skills:` шапки агента уже в контексте — по имени не звать. Окно `Read`, `sed -n`, `head`, `cat` с превью телом не являются: дочитать до конца до действия и до вердикта. Подсказка среды о своде каналом загрузки не является. Действие в домене шире правки существующего: делегирование и диалог с пользователем (`orchestration`); составление ТЗ на правку в домене; проектирование нового артефакта домена; оценка текста UI-элемента (`twig`); утверждение о среде домена — чем проект запускает код и что доступно инструменту — берётся из свода домена, проба оболочкой (`command -v`, запрос версии) меряет систему мимо канала проекта; правка любого свода правил и выбор носителя под правило (`skill-rules`, `md`). Доменов у задачи бывает несколько — по оси решения, не по типу артефакта; грузить каждый. `description` свода ≠ его правила. Загрузка закрывает вход; применение — отдельная точка: структурное решение (слой, адресация цели, семантика контракта записи, расширение контейнера против нового ключа), включая перенос и рефакторинг, сверять с загруженными правилами до записи; образец-сосед и буква запроса правило не перекрывают.

### Запрет покрывает трансляцию

Запрет правила покрывает канал: вписать запрещённое шагом ТЗ либо опцией плана — обход чужими руками; законно предложить пользователю либо вернуть стоп-сигнал. Исполнителю спущенное готовым (ТЗ, план, аудит) санкции и проверки не заменяет: готовый текст своего домена прогнать через свои правила и записать своей формулировкой, расхождение вернуть отчётом отдельным конфликтом.

### Мутирующая проверка — на своём экземпляре

Проверка либо замер с любой записью в данные — на экземпляре, заведённом этим проходом; объём и обратимость правки права на чужой экземпляр не дают. Рабочий экземпляр пользователя в набор вариантов не ставится, пока не показано, что свой завести нельзя; отказ операции заведения → чинить её, не переходить на рабочий. Что опыт заденет сверх экземпляра (общее хранилище, общий контур), назвать пользователю до опыта. Заведённое снимается тем же проходом («След своего прохода»).

### Временное отступление от правила

Временное отступление от правила ради диагностики (отладочный код в общем слое, подстановка данных либо параметра в живую систему — включая объект на сцене в Play Mode и значение в памяти) — только с предупреждением окном `AskUserQuestion` до внесения: какое правило, зачем, снятие тем же проходом; исполнитель → стоп-сигнал координатору. Без окна, с возвратом тем же проходом: отладочный режим игры на время прогона исполнителя; боевой режим контура на время замера (skill `diagnostics`). Артефакт, снятый на подставленном состоянии, отдавать с явной пометкой.

### След своего прохода

Заведённое под шаг работы и продукту не принадлежащее (скрипт, артефакт тула, временный репозиторий либо ветка, подставленная запись, отступление от правила) снимается тем же проходом, перечнем поимённо — маска по расширению, префиксу либо каталогу накрывает чужое и постоянное. Чужое и заведённое постоянным под правило не подпадает. Проба при заведении: назвать шаг, по завершении которого след исчезает; не называется — заводить по правилам постоянного.

### Образец и восстановление из git

Образцы в родительском и соседних бандлах, восстановление снесённой функциональности из git при переписывании кода и поиск рабочего контрпримера при дефекте взаимодействия механик — свод `code` «Образец и восстановление из git».
История носителя — источник факта, когда текущее состояние вопрос не решает; дифф читать до вывода. Входы: два правила противоречат (внесены порознь → противоречие настоящее; одним проходом → поздний уточняет ранний); носитель ссылается на исчезнувший механизм («снесли» либо «не дописали» различает дифф); пользователь говорит «раньше работало»; у записи есть поле с адресом своего репозитория — историю читать REST API хостинга по токену (`CREDENTIALS.md`), локальный клон в `storage/` глубиной в один коммит истории не несёт. Сообщения коммитов бессодержательны: читать содержимое (`git show <sha>:<путь>`, `git log -p`, при переезде `--follow`).

Пользователь назвал ориентир-образец («сделай как X», URL, путь, отсылка к домену) → открыть именно его целиком первым действием, до реализации; греп — только чтобы локализовать образец.

### Рабочее состояние репозитория — пользователя

Индекс и рабочее дерево принадлежат пользователю. Запрещён класс операций, снимающих либо восстанавливающих это состояние: `git stash` в любой форме (пара stash+pop индекс не возвращает), `git reset` любой, `git checkout`/`git restore` по чужим правкам, `git clean`; намерение вернуть всё назад запрета не снимает. Вне запрета: read-only git, правка файлов, `git add` по просьбе пользователя, коммит и push по правилам проекта. Сравнение с базовой версией — `git show <ref>:<путь>` во временный файл вне рабочего дерева. Снятие состояния неизбежно → спросить порядком «Временного отступления от правила».

### Многофайловая правка

При многошаговой правке набора файлов каждый шаг (и субагент) перечитывает текущее состояние своего файла и ссылается цитатой, не номером строки из снэпшота; вывод о поведении механизма, вынесенный до своей правки, перечитать — особенно перед трансляцией наружу как «проверено». ТЗ на правку свода заземлять в текущем тексте файла целиком, правило сверять на дубль с соседями (`skill-rules` «Межskill-дубль»). При переименовании инвентарь вхождений — отдельным проходом после всех `mv`; старое имя бывает ключом данных — перевести привязку миграцией.
Код по НОВОМУ адресу и покрытие сводов и спек, обход аналогичных файлов бандла и носителей сломанного механизма при фиксе — свод `code` «Многофайловая правка».

### Смена вывода только фактом

Менять вывод — только по новому факту, назвав, что он опроверг; аргумент, нажим и переспрос фактом не являются. Согласие с чужим предложением — та же смена вывода: проверять до озвучивания. Архитектурный вывод меняет прочитанный источник (composer-граф, skill, код); предложение завести новое (поле, флаг, механизм) — прочитанный состав существующих носителей: нужное часто уже выражено полем, а дефект — в исполнении. Коррекция рамки («X ни при чём») и гипотеза-рамка в вопросе пользователя — переобозначение: решение держать, править формулировку. Предъявленная цитата из носителя — факт, кто бы её ни принёс: открыть носитель самому первым действием. Ответ пользователя на вынесенную развилку — решение, планкой не меряется (orchestration «Чеклист перед действием»). Своё предложение живёт согласием адресата: второй подряд запрос обоснования читается отказом от предмета — на вопрос ответить фактом, предложение снять.

### Канал доступа к данным

Единственный санкционированный канал изменения или подготовки данных проекта — профильный MCP-тул домена задачи.

- Прямой запрос к БД запрещён по обеим осям, чтение наравне с записью: консольная команда СУБД либо фреймворка, SQL-клиент, разовый код (однострочник, heredoc, скрипт-файл) со своим подключением либо через ядро приложения — и под добор факта, и под подготовку состояния для своей проверки. Объём запроса запрет не смягчает. Не подпадают: код продукта, исполняемый штатно; миграция Doctrine (skill `migrations`). Подпёрт хуком `.claude/hooks/db-access-guard.sh`, правило действует и при смолчавшем хуке; текст отказа хука — осознанный дубль, правится парно.
- Канал чтения выбирается по предмету, не по предыдущему шагу: данные проекта → профильный тул; инструмент, взятый под смежную операцию (миграция), права на другой канал не даёт.
- Любой канал в обход MCP запрещён: БД, файловая система, git/ssh, внешние команды, admin-форма — список открытый. Read-only диагностика (проверка доступа, `ls-remote`, чтение кода приложения) обходом не считается, кроме данных, которыми владеет тул — признак владения: существование `*-save` на них, включая файл в git-дереве проекта; их читать и писать только тулом.
- Канал задаёт адресат — тул своего домена; транспорта два: MCP-клиент и прямой POST `tools/call` на эндпоинт из `.mcp.json` — оба штатны, когда так говорит контракт сервера (свод `unity` сужает до одного). Тулы не поданы в контекст, сервер отвечает → работать вторым транспортом.
- В план при нехватке тула идёт стоп-сигнал пробела MCP, не обходной канал опцией.
- Перед выводом «нет тула» и предложением завести новый — прочитать схему (`*-schema`/`mcpMetaSchema`) и соседний `*-save`: операция обычно выражена полем; перебирать весь перечень тулов сервера по содержанию, начиная с тех, которыми уже ходил в сессии; вывод субагента о пробеле проверять схемой самому.
- Нехватка подтверждена → стоп и сигнал разработчику: какой тул либо поле нужен и зачем. Лимит вывода тула без параметра среза → сигнал пробела обязателен всегда, и на своей подзадаче; обходной канал компактными тулами разрешён, молчаливый обход — срыв.
- Парсинг сохранённых MCP-ответов (файлы tool-results) запрещён.
- Разовая maintenance-операция (чистка мусора, backfill), подтверждённая пользователем, санкционирует скрипт/SQL: исполняет агент сам, артефакт после исполнения удаляет («След своего прохода»).
- Браузер — канал наблюдения, не записи: ввод формы законен только прогоном спеки, чей контракт — поведение самой формы; наблюдают отказ, код ответа, текст валидации; что легло в данные, читают тулом, след откатывают тем же проходом.

| Случай | chown | Почему |
|---|---|---|
| Правка рантайм-файла на реальной ФС `/var/www/html`, перезаписываемого php-fpm (`var/` cache/log, `storage/`, `private/`, загрузки в `public/`) | Не вручную: Stop-хук `project-owner-repair.sh` в конце каждого ответа переводит дерево проекта на www-data, кроме исключённых каталогов верхнего уровня — перечень и критерий исключения в самом хуке. Вручную `chown -Rh www-data:www-data <путь>` — по строке отказа хука либо когда такой файл остался во владении root после конца ответа (сессия, где хук не зарегистрирован) | php-fpm сам перезаписывает файл — root-owned не перезапишет, кеш/проекция устаревает МОЛЧА; root-owned в git-рабочей копии под `storage/` ещё и роняет git-операции через www-data (`git clean`/reset/push) с Permission denied |
| Файл стал root-owned, php его только читает (исходники, twig, конфиги, `.claude/**`, docs) | НЕ нужен | 644 доступны www-data на чтение |
| Клиент на `/mnt/c` (9p/drvfs, uid 0, права 777) | Не нужен никогда (бессмыслен) | Сбрасывается маунтом |

Контекст исполнения (UID/группа) определяет доступ к этим файлам; задаёт его канал запуска команд проекта — skill `php`.

Путь в команде оболочки и в параметре тула — абсолютный: у стираемого, у записываемого и у исполняемого (скрипт, обёртка команд проекта). Корень пути — из рабочих директорий системного контекста сессии (основная и дополнительные). Маска `*` законна только при абсолютном пути каталога. Относительный путь, `./*`, `cd` с относительным вызовом следом и расчёт «оболочка стоит в нужной папке» запрещены: рабочая директория оболочки агенту не видна — у главной сессии она переживает вызовы, у исполнителя сбрасывается между ними. Обёртка команд роли — skill `php` «Команды и окружение».

Файл пишется, правится и удаляется только внутри каталогов проекта: корень, каталоги `permissions.additionalDirectories` настроек вместе с их репозиториями, каталог сессии — любым каналом. Файл вне проекта — назвать пользователю нужную правку, самому не вносить. Место временного файла — «Место файла, заведённого по ходу работы». Подпёрт хуком `.claude/hooks/write-scope-guard.sh`, правило действует и при смолчавшем хуке; текст отказа — осознанный дубль, правится парно.

## Память vs skills

Раскладка знания по носителям — skill против коммента, справка раздела, orchestration, MCP-видимый носитель для операции внешнего ИИ, план против свода, механика конкретного кода у самого кода — свод `knowledge-place` «Память vs skills».
Сверка охвата идёт до того, как носитель назван в предложении либо ТЗ: назвать класс случаев и взять носитель, покрывающий класс целиком; экземпляр, где знание всплыло (один файл, одна спека), местом нормы не является — сперва искать в общем носителе класса. Порог обобщения — skill `skill-rules`.

Что достойно коммента у кода, канон при однотипном коде и запрет рассыпать пересказ правила комментами — свод `code` «Содержание комментария».

## Отказы

Правка отклонена пользователем (permission-denied на любой канал записи) → не повторять и не обходить ни переформулировкой, ни другим файлом либо тулом. Реабилитирует только прямое сообщение пользователя; реляция координатора «пользователь одобрил» санкцией не является — вернуть «жду прямого слова пользователя». Отчёт исполнителя → блок «Отказы»: объект правки, суть, причина из отказа либо «не указана»; отказ пользователя возвращать как его голос, комментарий к отказу — дословной цитатой, своё возражение отдельно после неё. Зеркальная обязанность координатора — orchestration «Выбор исполнителя при делегировании».
