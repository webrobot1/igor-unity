> **Ведомая копия.** Источник — `/var/www/html/game/.claude/skills/knowledge-place/SKILL.md` в серверном репозитории; копию перезаписывает его хук при каждой правке источника. Правка копии теряется молча — вносить её в источник. Серверного репозитория нет под рукой → назвать нужную правку пользователю.

Выбор носителя знания и владение путями свода правил, документации и конфигурации проекта. Сверка ОХВАТА класса случаев ДО называния носителя — `core` «Память vs skills».

## Память vs skills

Применимо к любому агенту/разработчику → skill. Узкое классу → коммент. Как работает конкретный admin-раздел (что где настраивается, сценарии) → справка раздела help, НЕ skill (механика — skill `admin` «Справка раздела»). Только моё поведение с этим пользователем → orchestration (манера) либо CLAUDE.md. Не дублировать.

Внешний ИИ через MCP-тул skill НЕ видит — носитель выбирает ОПЕРАЦИЯ, к которой знание прилагается, не ярлык знания («usage тула» против «доменной процедуры»): идёт MCP-тулами и вести её будет внешний ИИ → MCP-видимый носитель, не skill. Выбор конкретного носителя — `.claude/skills/mcp-text/SKILL.md` «Где что писать». Знание нужно нескольким аудиториям (локальный плюс внешний ИИ, человек) → ОДИН MCP-видимый носитель плюс ссылка из skill, не дубль в трёх местах (устареет молча). Проверять в момент записи; уже лежащее не там — переносить. Доступность тула внешнему ИИ потребителя не задаёт — квалифицирует его фактический сценарий операции (кто выполнит и сколько раз). Синхрон существующих параллельных носителей при смене поведения — `core` «Полнота охвата и проверки».

Задача по коду (зафиксировать расхождение, выровнять носитель, поправить провайдер, прогнать спеку) не предписывается текстом, чей предмет — действующее устройство: внешний AI-контракт, справка раздела, подпись в интерфейсе. Место задачи — план либо задача; описание устройства под запрет не подпадает.

durable-знание → skill по владению, не в план: план держит лишь эфемерное (статус, todo, дорожная карта будущих skill). Неоднозначно, куда писать, → сделать однозначным проверкой долговечности и конфликта с существующим правилом; неразрешимый анализом конфликт «правило X ↔ сделано иначе Y» → окно пользователю (orchestration «Непрерывное обучение»).

«Как работает конкретный код» (механика класса, пошаговый разбор реализации) → у кода, не в skill (коммент — лишь на ПОЧЕМУ по `code` «Содержание комментария»); skill держит переиспользуемые правила, ссылка на класс-образец — максимум при навигационной ценности. Знания об игровом фреймворке `storage/framework` — критерий носителя в skill `storage`.

## Правки конфигурации проекта

Свод правил, документацию и конфигурацию проекта правит только владелец пути:

- `.claude/skills/**`, markdown в корне проекта, `docs/`, `.install/`, markdown `.claude/**` вне зон ниже, `Build/*.md` и `Build/<бандл>/instructions.md` — `skill-editor`
- канон клиентского репозитория и канон репозитория узла — их корневые `CLAUDE.md` — `skill-editor`: ведомыми копиями серверного носителя они не являются, источника в серверном репозитории у них нет, правка идёт по месту. Исполнитель задачи в этом контуре в них не пишет — находку возвращает отчётом
- ведомая копия в этих контурах — с пометкой ведомости в голове файла — не принадлежит никому: её перезаписывает зеркалирование, правка в копию теряется молча, правка идёт в серверный источник, чей адрес называет сама пометка
- `.claude/agents/**`, `.claude/hooks/**`, `.claude/workflows/**` — главная сессия, кроме маркеров `.last` ниже; хук, его набор самопроверки и реестр хуков правятся по своду `gate-mechanics`
- `.claude/agents/<имя>.last` — агент этого имени и главная сессия
- `.claude/workflows/*.last` — главная сессия
- `.claude/settings.json` — главная сессия: файл несёт регистрацию хуков, его правкой снимается сама проверка владения
- настройки внешнего контура — `.claude/settings.json` репозитория клиента и репозитория узла — главная сессия: ими запускается копия гейта владения у той стороны, и снятая регистрация гасит копию молча, не дав отказа ни в одной из двух сессий

Зона задана носителями, не расширением имени: markdown вне названных мест — черновик, артефакт прогона в каталоге инструмента, README чужого репозитория внутри дерева (клон в `storage/`, снапшот, установленное окружение) — в перечень не входит. Путь вне перечня, включая `Plans/`, правит главная сессия. План — её рабочий артефакт, жизненный цикл которого она и так ведёт (`plan-lifecycle`); делегирование точечной правки несоразмерно дороже её объёма. PreToolUse-hook `skill-guard` блокирует остальных по agent_type.

Исключение из владения — точечная правка главной сессией пути, которым она не владеет: вносит сама, делегирование несоразмерно дороже объёма правки. Точечная правка — вызов `Edit` с непустым `old_string` и `new_string` до 10 строк включительно; порог общий с хуком `skill-guard`, правится парно. `Write` и `Edit` с пустым `old_string` — вставка файла либо раздела, не точечная правка; у команды оболочки меры текста замены нет вовсе. Вне исключения маркер `.last` (владение по имени носителя) и ведомые копии (владельца нет: правка любого размера теряется на сверке зеркала). Серию точечных правок закрывает проверяющий проход владельца пути (`orchestration` «Выбор исполнителя при делегировании»).
