Правка копии теряется молча — вносить её в источник. Серверного репозитория нет под рукой → назвать нужную правку пользователю.

Ведение план-файла: что в нём резать, по какому доказательству, чем вырез исполняется и что уходит с работой дальше. Выбор исполнителя под аудит статуса и обязанность перепроверять находки агентов — `orchestration` «Выбор исполнителя при делегировании». Что в план не пишут вовсе — `knowledge-place` «Память vs skills».

План — рабочий артефакт оркестратора, чистится по мере оседания работы в коде. Первым шагом аудита классифицировать план по направлению: forward-план изменения (цель, к которой идём; baseline = текущий код) либо запись сделанного. У forward-плана расхождение цели с текущим кодом ожидаемо — пункт открыт, а baseline, совпадающий с кодом, реализацией не является (`code` «Фактический вопрос ≠ нормативный»).
По завершении либо затихании работы пройти корпус: закрыт целиком → удалить файл; остался лишь прогон уже написанных спек и тестов, включая отложенный либо отменённый пользователем, → переспросить явно ещё раз (прогнать сейчас либо удалить вместе со списком) и удалить; закрыт частично → вырезать сделанное; разрозненные остатки многих планов → свести в один backlog по подтверждению. Статус каждого пункта в обе стороны доказывать чтением кода либо артефакта, не маркером плана; второй канал закрытия — решение, принятое в диалоге: вырез тем же ходом, где оно прозвучало. Не-пунктовый текст (преамбула, шапка, принцип) стареет наравне с пунктами. Однозначно закрытое вырезать автономно, без подтверждения; неоднозначное (спорная закрытость, продуктовая отложка) — доложить либо спросить. После подрезки либо при остановке с остатком — доложить: что вырезано, что осталось, путь к плану ссылкой («Манера общения»). Точка обязательного аудита — момент «реализация завершена, предлагаю прогон тестов»: вместе с предложением вырезать закрытое и доложить остаток.

ЗАКРЫТЫМ пункт делает НАЗВАННЫЙ исход, не отсутствие работы по нему. Таблица ниже решает судьбу ОДНОГО пункта; судьбу файла целиком решает абзац выше — по нему же идёт план, где не осталось ничего, кроме прогона.

| Исход пункта | Что с ним |
|---|---|
| вердикт координатора «действие не требуется»; решение пользователя «оставить как есть» / «не делать» | закрыт → вырезать |
| ожидание наблюдения: наблюдать сейчас нечего, вернётся условие — посмотрим; вопрос, всплывший по ходу и отложенный на потом | открыт → план живёт |
| не начатое, пользователем не решённое: идея, кандидат | открыт → подать предложением окном `AskUserQuestion` в финальном блоке («Манера общения»); перечень в тексте ответа подачей не является |

За отложенным наблюдением стоит незакрытый вопрос; молчание пользователя закрытием не является — не спрошенное не решено. Строку исхода «не начатое, пользователем не решённое» воспроизводит `.claude/hooks/plan-hygiene-reminder.sh` — осознанный дубль, правится парно.

Закрывающим исход делает решение, прозвучавшее в диалоге; запись в теле плана статуса не несёт — отложенное и «не делать» ложатся в текст одинаково. Исход прочитан только из текста плана → пункт открыт, подаётся пользователю.

Пункт-вопрос статуса не имеет: проверяется его посылка об устройстве кода либо интерфейса (посылка о видимом потребителю — носителем показа: шаблоном и подписями). Подтвердилась → подать окном по таблице; нет → назвать пользователю фактическое устройство, решение за ним.

ФОРМА выреза: закрытый пункт уходит из файла целиком. Зачёркивание, приписка «закрыто» либо «опровергнуто», раздел «Сделано» вырезом не являются — пишешь такое слово → вырезать пункт. Факт о сделанном, нужный следующему шагу по открытому пункту (что проверено и переделывать не нужно, какое решение принято, чего не трогать), остаётся строкой-контекстом у пункта либо в шапке; осевшее в своём носителе не пересказывается, строка отсылает к носителю. Чего в план не пишут вовсе — `knowledge-place` «Память vs skills».

План пополняется тем же ходом, где вводная прозвучала: решение пользователя, меняющее объём открытого пункта; факт, опровергающий его посылку; носитель, который придётся править вместе с пунктом. Ход работы и промежуточное наблюдение вводной не являются.

Просьба о плане начинается с вопроса, у какой работы просят план, и с поиска её плана в корпусе: план есть → писать в него; новый файл — только у работы без плана. Свой план — созданный тобой либо тот, по которому ты продолжаешь работу; план работы другой сессии не правится и не удаляется, под свой остаток заводится свой файл. Перенос пункта между планами — вырез из источника.

Работа передаётся дальше (новая сессия, другой исполнитель) → до объявления передачи план своей работы сверяется с остатком, дописывается недостающее. Состав остатка: незакрытые требования пользователя, непроверенное и почему, проверенное и не требующее переделки, следы в данных от прогонов, носитель исполнения каждого открытого шага (где лежит, каким каналом правится, чем проверяется). Тот же перечень несёт `.claude/hooks/precompact-remainder.sh` — осознанный дубль, правится парно; после сжатия истории первым ходом сверить план с остатком из сводки. Отложенный полный проход по зоне аудита → явный пункт «по завершении — поставить маркер» (`workflow-runs`). Объявляя передачу, назвать путь к файлу плана ссылкой (`orchestration` «Манера общения»). Новую сессию открывает пользователь сам: координатор её не поднимает и команду запуска не выдаёт; подъём процесса поверх живой сессии и увод работы фоном запрещены — гейт `.claude/hooks/claude-session-guard.sh`, текст его отказа — осознанный дубль, правится парно.

Передав работу дальше, координатор по ней останавливается: план не правит и не режет, вопросов по его пунктам не задаёт, работ не начинает — до возврата работы. Вырез закрытого, приёмка сделанного и ответы по пунктам делаются до объявления передачи; напоминание хука на завершении ответа — наблюдение, не поручение.
