## Гигиена браузера

Инстанс браузера один на всех — держать открытым ровно на время самой браузерной работы: следующая сессия либо агент упрётся в блок «Browser is already in use».

- Открыл сам — сам и закрываю: `browser_close`, как только браузер не нужен ближайшими шагами — уход в серию правок кода, смена задачи, конец проверки, финальный отчёт, долгий не-браузерный этап между браузерными шагами (прогон проверок, замер анализатором, добор данных штатным каналом, ожидание чужого исполнителя). Решает нужда ближайших шагов, не ощущение «закончил»: явного «закончил» при чередовании проверок с правками не наступает. Подготовительный шаг той же браузерной работы закрытия не требует — правка файла, результат которой прямо сейчас уходит в уже открытую страницу (собранный текст либо картинка под вставку); закрытие между такими шагами теряет несохранённое состояние страницы. Общее намерение продолжить подготовительным шагом не является — как и не-браузерный этап, чей результат в открытую страницу не уходит: на его время браузер закрывается, хотя браузерная работа не закончена и продолжится после. Намерение вернуться и оценка «этап короткий» держать открытым не разрешают — длительность следующего этапа оценивается до него и систематически занижена, повторное открытие стоит одного вызова против блокировки чужой сессии на неопределённый срок. Чек в конце каждого хода: браузер открыт, а ближайший шаг его не требует → `browser_close`. На завершении ответа и перед окном вопроса человеку свой открытый браузер закрывает хук `.claude/hooks/shared-playwright-close-reminder.sh`, правило действует и при смолчавшем хуке; закрытие по ходу работы остаётся за вызывающим.
- Знание об открытости браузера даёт вызов закрытия, не память о своих прошлых закрытиях: между прошлым закрытием и текущим шагом лежит повторное открытие, и «я же закрывал» относится к прежнему эпизоду. Напоминание хука об открытом браузере памятью не проверяется — реакция на него одна: `browser_close`. Вызов дёшев и повторим: браузер уже закрыт — ответ безвреден, инстанс занят чужой сессией — приходит отказ.
- Параметр имени файлового артефакта тула (скриншот, дамп сетевых запросов, снапшот страницы) либо не передавать вовсе, либо задавать абсолютным путём в каталог инструмента `.playwright-mcp` в корне проекта (`shared-core` «Место файла, заведённого по ходу работы», `shared-core` «Файлы»). Путь вне корней сервера Playwright он отбивает отказом «outside allowed roots»: каталог сессии в его корни не входит, вызов пропадает впустую. Артефакт, который должен пережить закрытие браузера (материал продукта), под адресом из своего вызова не остаётся: адрес, названный параметром вызова, хук уборки снимает следом за `browser_close`. Такой артефакт кладётся на место назначения тем же проходом, что съёмка, — каналом приёма самого места; по новому адресу уборка его не находит. Описание тула обещает обратное (относительное имя остаётся в каталоге инструмента) — на дефолт не полагаться.
- Свои браузерные артефакты в каталоге инструмента снимает хук `.claude/hooks/shared-playwright-artifacts-clean.sh` следом за своим `browser_close`; своя обязанность тут — само закрытие. Прочего в каталоге хук не касается: чужие файлы и собственные рабочие материалы задачи остаются, своё снимает сам вызывающий (`shared-core` «След своего прохода»). Вручную каталог не чистить: типовой промах ручной уборки — маска по текущей директории, сносящая файлы корня проекта (`shared-core` «Файлы»). Отчётная строка об уборке приходит не на каждое закрытие — её отсутствие ручную уборку не разрешает.
- Открыл не я — не трогаю: вкладка браузера пользователя за собой не закрывается, инстанс под чужой сессией не закрывать и артефакты его не чистить (отказ «браузер занят» → уборки нет вовсе).

## Приёмы браузерной автоматизации

- Ввод формы страницы проекта — только прогоном спеки, чей контракт — сама форма (`shared-core` «Канал доступа к данным»); иначе форму, изменённую в коде, в браузере проверяют лишь показом страницы.
- Отладочный режим включён → служебная панель фреймворка (профайлер и т.п.) лежит поверх страницы и попадает в кадр: скрывать её перед снимком, не вырезать обрезкой после.
- Клик берёт первый элемент под селектор. Цель отбирать признаком, однозначным для неё (текст кнопки): класс либо тип цель не идентифицируют — повторяются на странице. Однозначного признака нет → перед кликом сверить число совпадений селектора и позицию цели среди них.
- Команда не завершилась, а действие не произошло → первым исключить блокиратор вне разметки страницы: нативный диалог ОС держит вкладку, а снимок страницы его не несёт — оттого и диагностика инструмента (указание на блокирующий JS-диалог, «страница правку не принимает»), и сам снимок уводят внутрь страницы, где причины нет. Типовой источник — клик, попавший в чужую кнопку загрузки файла. Разметку и селекторы разбирать после того, как блокиратор исключён.
- Файловый диалог Playwright перехватывает штатно: клик по кнопке загрузки → `browser_file_upload` с абсолютным путём. Не перехватило → запасной приём патчем `HTMLInputElement.prototype.click`→upload. Оригинальный `click` восстановить сразу после загрузки — иначе у пользователя перестаёт открываться ручной файловый диалог. Kapture путь файлового диалога не проходит, но файл кладётся в поле выбора файла кодом страницы (`evaluate`, нужно разрешение исполнения во вкладке): перехватить `HTMLInputElement.prototype.click` у поля `type=file` и нажать кнопку загрузки, файл получить `fetch` с временного локального сервера, отдающего его с заголовком `Access-Control-Allow-Origin`, положить в перехваченное поле через `DataTransfer` и поднять событие `change`, оригинальный `click` восстановить; сервер снять тем же проходом. Разрешения исполнения во вкладке нет и Playwright занят — дальше по `shared-core` «Нужный ресурс недоступен».
- Диалог ОС (выбор цвета, шрифта) Playwright недоступен — ограничение инструмента, не сайта. Обход: буфер обмена плюс `Ctrl+V`, вызов API страницы либо шаг человека.
- Каталог файла на загрузку ограничен рабочим каталогом проекта и каталогом инструмента: путь во временный каталог сессии отклоняется. Готовый файл копировать в разрешённый каталог перед загрузкой.
- Редактор либо компонент, ведущий собственную модель содержимого, сериализует из неё: прямая мутация DOM либо поля ввода теряется. Менять только его публичным API — командой редактора, установкой состояния, сбросом через жизненный цикл.
- Поле с автоподсказкой либо автодополнением искажает посимвольный ввод: записанное сверить с задуманным до следующего шага.

## Kapture: вкладка браузера пользователя

Kapture ведёт из WSL реальный Chrome на Windows — вкладку, уже залогиненную пользователем: своего входа агент не делает.

- Без фокуса окна работают тулы `fill`, `keypress`, `dom`, `elements`, `navigate`, `reload`. Активного окна Chrome требуют тулы `click`, `screenshot` и раскрытие свёрнутого блока тулами
- `fill` заменяет содержимое поля целиком, переносы строк сохраняются
- Сохранение тулами — `keypress Enter` по кнопке сохранения, не `click`. Коммит через `keypress` проходит только при окне Chrome в фокусе ОС: на время такого прогона пользователь держит фокус и компьютера не трогает
- Поток правки: navigate → fill → keypress по кнопке сохранения → проверка записи по состоянию кнопки в `dom`. Записанное не предполагать
- Действие кодом страницы (`evaluate`: `el.click()`, `execCommand`, событие клавиши из кода) фокуса окна и показанной вкладки не требует. Отклику страницы, который ждёт кадра анимации, нужна показанная вкладка. Временный локальный сервер в WSL страница вкладки достаёт по адресу `127.0.0.1` (наблюдение 27.09.2026)
- Прогресс длинного прогона вести в отдельном рабочем файле: он переживает рестарты и суммаризацию
- Кадр со вкладки браузера пользователя (скриншот страницы либо по селектору) принимать только после проверки поля видимости вкладки в ответе тула: вкладка невидима — кадр ложно-пуст (белый лист) при полностью отрисованном DOM. Команда вывода вкладки на передний план подтверждает лишь приём: окно браузера у пользователя не на переднем плане — поле видимости остаётся отрицательным и в последующих ответах. Скрытой вкладке браузер не выдаёт кадров анимации (`requestAnimationFrame`) — отрисовка замирает на произвольной стадии, частичный кадр читается дефектом «слой не рисуется», ожидание завершения не лечит. Пустой кадр либо висящие заглушки загрузки — повод перемерить видимость, не диагноз дефекта своей вёрстки или рендера. Видимость не наступила → показать вкладку командой Kapture, затем вывести окно браузера на передний план самому (заголовок окна — заголовок показанной вкладки): `powershell.exe -NoProfile -Command "(New-Object -ComObject WScript.Shell).AppActivate('<заголовок вкладки>')"`, успех — поле видимости в ответе Kapture. Не наступила и после — снимать своим Playwright; он занят — ресурс удерживается сессией пользователя, дальше по `shared-core` «Нужный ресурс недоступен».
