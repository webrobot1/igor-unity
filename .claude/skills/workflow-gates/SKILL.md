# Гейты проекта

Гейт — действие, которое выполняется только по прямому поручению автора либо по подтверждению своего предложения; по подтверждению действие выполняет сам предложивший (`orchestration` «Самостоятельность»). Подписи актора — словарь skill `flow-rules`, автор тут — владелец проекта. Исполняет действие агент при любом акторе. Условие строки не выполнено → действие не выполняется, ничего не меняется: главная сессия предлагает действие автору, исполнитель возвращает стоп-сигнал координатору. Разрешение выполнять гейтованное действие («миграции сам выполняй», «тесты запускай сам») действует до конца текущей сессии — новая сессия спрашивает его заново; гейта разрешение не снимает и основанием предложить снятие не служит: гейт снимается только правкой этого свода по отдельному решению автора. Карт-бланш на очередь задач гейта не снимает — разрешение спрашивается отдельно. Механика программы под гейтом — правило прав, хук — skill `gate-mechanics`; паритет текста и механики — спека `test-gate-mechanics-parity`.

## Проверка правки

| Актор | Действие | Состояние | Условие | Событие | Спека |
|---|---|---|---|---|---|
| автор | Прогон тестирования | задача с правкой кода завершена; у серии однотипных массовых правок (аудит-фикс по бандлам, миграция, свип и т.п.) задача — серия целиком, её граница — как у пост-задачного итога (`orchestration` «Непрерывное обучение») | подтверждение предложения «Запустить тестирование?» либо прямое поручение | правка проверена спеками по изменённым файлам (отбор — skill `spec-run` «Отбор по изменённым файлам»), клиентская правка — в Play Mode, справки задетых разделов и описания правленных элементов игры — ревью текста; автор получает, что сломано и что не проверено | |
| автор | Прицельный прогон спеки | изменён носитель, объявленный спекой `runner: prompt` — `test-*` и `sandbox-*` наравне: файл из её `paths` либо носитель, названный её описанием либо телом (раскладка носителей по каналам — skill `spec-rules`) | подтверждение предложения прицельного прогона либо прямое поручение | контракт спеки подтверждён либо вскрыта регрессия кода либо устаревание спеки; у серии — одной пачкой по всем затронутым спекам финалом серии | |
| агент | Прогон спеки `runner: phpunit` либо теста сервера | изменён носитель, объявленный спекой (файл из её `paths` либо носитель, названный её описанием либо телом), либо код, который проверяет тест | нет — тест данных проекта не пишет, к игровому серверу и базе проекта не обращается | выполнено сразу, без предложения автору: контракт подтверждён либо вскрыта регрессия кода либо устаревание спеки либо теста; исход входит в итог прогона тестирования без повторного прогона | |

Гейт стоит на самоинициированный прогон спек `runner: prompt` и тестов клиента. Правка тест-инфраструктуры (phpunit.xml, bootstrap, тест-конфиги и т.п.) — под тем же гейтом. Проверка только что сделанной клиентской правки либо этапа в Play Mode — вход в игру, «работает ли», кадр — часть самой задачи и идёт без подтверждения; когда именно — skill `unity` «Запуск и закрытие редактора». Путь `paths` спеки `runner: prompt`, разворачивающийся в дереве в число файлов от порога корпусности, гейта прицельного прогона не открывает: такая спека проверяет инвариант по всему корпусу, её прогон идёт по накоплению (критерий и порог — skill `spec-run` «Отбор по изменённым файлам»). Прогон тестирования и прицельный прогон — разные гейты: первый проверяет правку целиком, второй — одну спеку по её носителям.

## Локальный контур

Локальная разработка целиком тестовая: база, игровой сервер с песочницей и код — продакшна в этом контуре нет, восстановление дёшево. Граница свободного — обратимость, не место: вопрос ставится о возвратимости стираемого, не о совпадении с перечнем команд. Рабочее состояние репозитория — индекс и рабочее дерево — послаблением не покрыто (`core` «Рабочее состояние репозитория — пользователя»).

| Актор | Действие | Состояние | Условие | Событие | Спека |
|---|---|---|---|---|---|
| агент | Уронить, перезапустить, сбросить либо пересоздать локальный процесс и данные | стёртое возвращают перезапуск, пересоздание либо повторная сборка, включая переустановку из репозитория | нет | выполнено сразу, без предложения и без развилки автору | |
| автор | Операция, необратимая по ДАННЫМ (полный сброс игры, удаление игрока, сброс своих правок поверх базовой версии и т.п.) | стёртого не возвращают ни перезапуск процесса, ни пересоздание кеша, ни переустановка из репозитория | подтверждение либо прямое поручение — и внутри локального контура | событие операции — её свод: skill `workflow-git-sync`, skill `workflow-element-lifecycle` | |
| автор | Необратимое вне локального контура (git push, публикация статей, отправка наружу и т.п.) | исход лежит во внешней системе либо в чужих данных, своими средствами не возвращается | подтверждение либо прямое поручение; созидающая операция на git-хостинге проекта — исключение («Git-хостинг проекта» ниже) | событие операции — её свод: отправка — skill `workflow-git-sync`, публикация части серии — skill `workflow-article-release` и т.п. | |

Правка, которая уходит в постоянный репозиторий проекта — содержимое игры, её фреймворка и библиотек, миров, анимаций, наборов картинок, — вносится только в игру 1. Прочие игры локального контура — стенды: их правки в постоянные репозитории не отправляются, а то, что стенд дал и что нужно сохранить, переносится в игру 1. Временный репозиторий прогона спеки постоянным не считается.

## Git-хостинг проекта

Доступ к репозиториям проекта — токен по HTTPS, ssh отключён; публичный репозиторий читается без токена. Право токена — уровень хостинга: существование репозитория и ветки, первичная инициализация; данные и код проекта (игры, фреймворки, библиотеки, контент и т.п.) им не покрыты — их канал прежний (skill `workflow-git-sync`).

| Актор | Действие | Состояние | Условие | Событие | Спека |
|---|---|---|---|---|---|
| агент | Создать репозиторий либо ветку, инициализировать пустой репозиторий первым коммитом, отправить без перезаписи чужой истории | репозиторий проекта на его git-хостинге | нет — право дано заранее и дословно: «у тебя access token - ты можешь создать что угодно» | выполнено без развилки автору; своего тула под операцию нет → токеном напрямую, API хостинга либо git | |
| агент | Удалить репозиторий | репозиторий проекта на его git-хостинге | нет — право дано автором дословно: «давай сделаем удаление репозитория разрешенной процедурой что бы не спрашивать меня» | репозиторий удалён вместе с историей, его копия на сервере снесена | test-image-set-guards, test-entity-guards, test-pull-push-logic, test-catalog-sync |
| автор | Удалить ветку, отправить с перезаписью чужих коммитов (force) | любое | подтверждение либо прямое поручение — гейт необратимого вне локального контура | ветка удалена; при перезаписи своя версия легла поверх чужих коммитов, они остались в истории (skill `workflow-git-sync` «Отправка») | |

Имя и адрес репозитория — описание параметров `name` и `path` тула `repo-create`. Группа и подгруппа под контент (тула на них нет) называются по той же норме: отображаемое имя на языке самого контента, адрес — латиницей, пунктуация имени приводится к допустимому хостингом. Официальные группы, их адреса и соответствие группа→тип контента — enum `GitGroup`.

Репозиторий контента заводится на один агрегат — мир целиком, анимацию, набор картинок; подгруппа группирует репозитории по происхождению арта. Контент, взятый со стороны, ложится в подгруппу своего источника — игры, из которой взят арт, либо владельца формата, чьи примеры выложены (суффикс подгруппы — имя источника), не в плоскую группу типа. Новый графический набор, нарисованный в проекте для игры-источника, — ремастер: подгруппа с суффиксом `-remaster`, репозиторий заводится закрытым, его карточка каталога — скрытой (public): витрина её не показывает, свой git-цикл идёт по адресу с токеном и от видимости карточки не зависит. Переработка взятого — подгонка размера, обрезка, смещение, перенос преград со слоёв в тайлы, пересборка той же графики в другой формат — ремастером не является и остаётся в подгруппе источника. Оригинал не перезаписывают: ремастер идёт своим репозиторием, исходный остаётся точкой отсчёта.

## Корпус правил и проходы

| Актор | Действие | Состояние | Условие | Событие | Спека |
|---|---|---|---|---|---|
| автор | Записать правило в свод, `CLAUDE.md` либо спеку | коррекция подхода, неочевидное решение либо паттерн, в сводах не описанные | подтверждение предложения фиксации либо прямое поручение | правило записано владельцем пути (`knowledge-place` «Правки конфигурации проекта») | |
| автор | Завести новую спеку | вскрыт контракт поведения на границе, спекой не покрытый; порог существования спеки пройден (skill `spec-rules`) | подтверждение предложения либо прямое поручение | спека заведена | |
| автор | Править спеку после её падения на прогоне | прогон спеки упал: регрессия кода либо устаревание спеки | подтверждение предложения либо прямое поручение | спека приведена к подтверждённому контракту | |
| автор | Начать дорогой аудиторский проход — массовый аудит, ревью, миграцию либо свип, не вмещающиеся в один контекст | накопление зоны от маркера последнего прохода (skill `fileagent`) | прямое поручение либо подтверждение предложения окном с ценой, что проход даст и сдвинет ли маркер | проход идёт порциями, все порции — один контекст, не веер субагентов; расход записан (кто ведёт проход и запись расхода — skill `audit-runs`) | |

Обновление существующей спеки под исход, сменённый заказанной либо одобренной правкой, свободно: вносит владелец пути, называется строкой итога.
